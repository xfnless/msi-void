# Text Vault 设计规格

## 1. 目标

Text Vault 是一个单用户、搜索优先、客户端加密的通用记录工具。第一版优先做到可日常使用：打开后快速搜索，选择条目，编辑纯文本，明确手动保存，并在桌面与临时使用的手机浏览器之间同步密文。

系统采用类似 Windows 记事本的保存心智模型：只有明确执行“保存”才会改变持久数据。程序不自动提交正文，不承诺恢复未保存的修改，也不以模糊状态掩盖保存失败。

长期方向是“数据—查询—视图”架构：条目可逐步增加属性，查询产生对象集合，多个视图展示同一集合。第一版只开放纯文本列表和编辑器，但底层对象格式不得阻碍以后增加表格、看板、日历、关系和附件。

## 2. 第一版范围

第一版包括：

- 单用户保险库的创建、解锁与锁定。
- 浏览器端加密和解密，服务器只存储密文。
- 一个条目一份自由纯文本；条目无需用户填写标题。
- 解锁后在前端内存中实时全文搜索。
- 创建、选择、编辑和手动保存条目。
- 多个搜索标签；当前查询可以固定到底部标签栏。
- 桌面端左侧搜索结果、右侧内容编辑器、底部标签栏。
- 手机端顶部搜索栏、中间列表或内容、底部标签栏。
- 手动保存时同时提交正文变化与工作区快照。
- 使用 revision 检测并发修改，禁止静默覆盖。
- 明确显示已保存、未保存、保存中、保存失败和冲突状态。
- 密文数据目录可直接备份和迁移。

第一版不包括：

- 自动保存正文、自动草稿或崩溃恢复。
- 离线编辑或离线阅读保证。
- 附件、Markdown 预览、富文本编辑。
- 属性编辑器、查询语言、表格、看板、日历或关系图。
- 自动填充浏览器密码。
- 多用户、分享、权限系统、AI 和服务端全文搜索。
- 服务端定时任务、提醒或自动化。

## 3. 技术架构

项目位于 `apps/text-vault`。

前端使用无需构建的 JavaScript 与 VanJS。它负责应用状态、客户端加密、全文搜索、查询标签、编辑交互和所有视图渲染。

后端使用 Go 标准库。它负责登录会话、密文对象 API、revision 条件写入、原子文件落盘、静态资源服务及必要的备份导出。前端资源通过 `embed` 打入单个 Go 可执行文件。

生产部署由一个 Go 二进制、一个数据目录及 HTTPS 反向代理组成。服务器不安装 Node.js，也不执行前端业务逻辑。

逻辑分层如下：

```text
UI 与视图
    ↓
查询与工作区状态
    ↓
内存对象仓库
    ↓
加密边界
    ↓
密文同步 API
    ↓
原子文件存储
```

每一层只依赖其下一层的公开接口，避免 UI、加密算法和存储格式相互耦合。

## 4. 通用对象模型

解锁后的逻辑对象采用带版本号的通用格式：

```js
{
  schemaVersion: 1,
  id: "随机且不可预测的 ID",
  kind: "entry",
  text: "自由纯文本",
  properties: {},
  createdAt: "ISO-8601 时间",
  updatedAt: "ISO-8601 时间",
  revision: 1
}
```

第一版中 `kind` 固定为 `entry`，`properties` 保持空对象且不在界面显示。保留它们是为了以后增加可选属性、查询和视图时不必替换对象身份或迁移正文模型。

标题不是必填数据。列表摘要可从正文第一段或匹配片段派生，不写回条目。

以后增加的保存查询和视图也使用对象身份，但必须具有各自明确的 schema，不将任意配置塞进条目正文。

## 5. 密文存储模型

服务器数据目录为：

```text
data/
├── vault.json
├── entries/
│   └── <object-id>.json
└── workspace.json
```

每个密文文件包含服务器执行同步所需的最少外层信息，例如对象 ID、schema 版本、revision、随机 nonce 和 ciphertext。正文、属性、查询词、当前选择及其他工作区内容均在密文内。

服务器可见对象数量、密文大小、修改时间和 revision 等同步元数据，但看不到正文、属性、搜索词或工作区内容。该元数据泄露是第一版明确接受的边界。

每次写入使用临时文件、同步落盘和同目录原子重命名。更新请求必须携带客户端读取时的 revision；不匹配时服务器返回冲突，不覆盖现有文件。

## 6. 密钥模型

创建保险库时，浏览器生成随机保险库数据密钥。用户口令通过带独立盐值的密码密钥派生流程生成解锁密钥；解锁密钥只负责包裹数据密钥。每个对象使用数据密钥、唯一随机 nonce 和带认证加密分别加密。

这样修改口令只需重新包裹数据密钥，无需重新加密全部对象。具体算法、参数、格式版本和迁移规则在实现计划中根据当前浏览器支持与权威安全建议确定，不允许自行设计密码算法。

明文和解开的数据密钥只存在于已解锁页面的运行内存。锁定时清空应用仓库、搜索索引、编辑器和密钥引用。实现不得声称 JavaScript 能保证物理内存被安全擦除；安全目标是停止应用继续持有和展示这些引用。

## 7. 搜索与查询演进

第一版解锁后获取全部条目密文，在浏览器中解密，并建立简单内存对象仓库。全文搜索对正文执行大小写不敏感的匹配，返回条目 ID 与匹配摘要。

目标规模为日常数百到一千条，设计上支持约一万条普通文本记录。第一版无需数据库全文索引。列表必须虚拟化或限制实际渲染节点数，避免结果数量直接扩大 DOM。

如果搜索计算开始影响交互，可在保持查询接口不变的情况下依次增加 Web Worker、增量倒排索引和持久化加密缓存。不得为了尚未出现的规模提前引入服务器明文索引。

未来查询层接受自由文本条件和结构化属性条件，输出稳定的对象 ID 集合；列表、表格、看板和日历只消费查询结果，不复制条目数据。

## 8. 手动保存语义

编辑器载入条目时保存其基准正文和 revision。任何正文变化都立即将当前编辑会话标记为未保存，但不写入 IndexedDB、localStorage 或服务器。

执行保存时：

1. 捕获当前正文和工作区快照。
2. 加密发生变化的条目和工作区。
3. 使用基准 revision 条件提交条目。
4. 条目成功后提交工作区快照。
5. 全部必要提交成功后才显示“已保存”。

如果条目提交成功但工作区提交失败，正文不得被标记为丢失；界面显示“正文已保存，布局未保存”，并允许仅重试工作区。各资源的状态必须分别记录，避免假装原子跨文件事务。

保存失败时编辑内容继续保留在当前页面内存中，显示可见错误并提供重试。页面刷新或进程终止后，最后一次成功保存之后的内容可能丢失，这是产品明确行为。

## 9. 离开保护

以下应用内部动作在存在未保存正文时必须被阻止：

- 切换条目。
- 切换底部搜索标签。
- 关闭当前搜索标签。
- 新建条目并替换编辑区。
- 锁定保险库。

确认框提供“保存并继续”“放弃并继续”“取消”三个动作。保存失败时不得继续导航。

页面刷新和浏览器关闭时注册标准 `beforeunload` 保护。产品不得承诺浏览器一定显示警告：iOS 杀后台、系统终止进程及部分浏览器策略可能绕过事件。界面通过持续可见的未保存标志帮助用户形成手动保存习惯。

## 10. 工作区与标签

工作区快照包含：

```js
{
  schemaVersion: 1,
  activeTabId: "...",
  tabs: [
    {
      id: "...",
      query: "...",
      selectedEntryId: "...",
      listScrollTop: 0
    }
  ],
  splitRatio: 0.36,
  theme: "warm-paper"
}
```

工作区只在用户执行保存时持久化。标签切换、搜索词、滚动位置和分栏调整会立即改变内存工作区，但刷新后只恢复最后一次成功保存的快照。

搜索词不得写入 URL、浏览器历史、localStorage 或分析日志。URL 最多包含无语义且不可预测的对象 ID；第一版可以完全不以 URL 表达工作区。

## 11. 界面行为

桌面端维持三部分：左侧搜索框和结果列表、右侧纯文本编辑器、底部横向标签栏。左右分栏比例可拖动，保存后进入工作区快照。

手机端不缩小桌面双栏：顶部为搜索、返回、保存及状态；中间一次只显示结果列表或当前条目；底部为可横向滚动的搜索标签栏。选择结果进入内容，返回时恢复该标签的查询、结果和内存滚动位置。

视觉采用暖白纸张、深棕文字、暗红强调、细分隔线和克制阴影，借鉴锤子便签的工具感。正文、IP、域名、命令和凭据内容优先保证可读与可复制，装饰不得牺牲密度或触摸目标尺寸。

## 12. 错误与冲突

所有网络和持久化操作均具有明确状态，禁止仅用短暂 Toast 表达关键失败。

revision 冲突时停止保存，保留当前内存文本，并获取服务器最新版本。第一版至少提供：复制当前未保存文本、查看服务器版本、放弃本地修改三个安全动作。不得自动合并或覆盖。

解密认证失败视为数据损坏、密钥不匹配或格式不受支持，不把残缺内容交给上层。单个对象失败时隔离该对象并显示对象 ID，其他可解密对象仍允许只读查看；在问题处理前禁止会扩大损坏的批量写入。

## 13. API 边界

第一版 API 只需要：

- 创建或读取保险库头。
- 列出密文条目及 revision。
- 获取单个或批量密文条目。
- 条件创建或更新密文条目。
- 读取和条件更新密文工作区。
- 创建、验证和注销单用户会话。
- 导出完整密文数据包。

API 不接受全文查询，不理解条目属性，也不返回解密内容。所有写接口限制请求大小、校验对象 ID 格式并采用同源会话与 CSRF 防护。公网部署必须位于 HTTPS 后。

## 14. 备份与恢复

运行数据不提交到 `msi-void` Git 仓库。项目提供明确的 `.gitignore`，并将 `data/`、备份包和本地配置排除。

备份以整个密文数据目录或一致性密文归档为单位。恢复测试必须证明：在空目录启动新实例、放入备份、使用原口令解锁后，条目与工作区均可读取。未经验证的多份复制不视为可靠备份。

## 15. 测试与日用验收

必须覆盖：

- 加密后服务器文件不包含已知正文和搜索词。
- 正确口令可解锁，错误口令不产生部分明文。
- 创建、编辑、手动保存和重新解锁后内容一致。
- 未保存时切换条目、标签和锁定均被阻止。
- 放弃修改恢复最后一次保存内容。
- 保存失败不清除编辑器内容，也不显示已保存。
- 两个客户端基于同一 revision 保存时，后提交者得到冲突。
- 工作区只恢复最后一次保存的标签、查询和布局。
- 桌面左右布局和手机列表/内容切换均可操作。
- iPhone 浏览器中输入框不触发页面整体缩放，键盘出现时保存与返回仍可达。
- 密文备份可以在空实例中恢复。

第一版达到“可日用”的标准是：连续使用过程中没有静默丢失已保存数据、没有静默覆盖冲突、所有未保存状态始终可见，并能从实际备份完成一次恢复演练。

## 16. 后续扩展边界

后续功能按独立增量加入：

1. 可选属性编辑和结构化查询。
2. 保存的查询与表格、看板、日历视图。
3. 条目关系和双向链接。
4. Markdown 阅读视图。
5. 附件对象与按需下载解密。
6. 可选的本地加密草稿恢复。

这些扩展复用对象仓库、查询接口、加密边界与密文 API。任何需要服务端读取数据的提醒、自动化或协作功能都必须重新评估客户端加密的安全边界，不能作为无影响的小功能加入。
