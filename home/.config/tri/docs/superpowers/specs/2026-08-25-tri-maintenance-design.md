# tri 长期维护设计

## 目标

在不增加功能、不改变键位、布局语义和视觉行为的前提下，提高 tri 的协议正确性、可测试性、故障可诊断性和长期可维护性。

后续简化决定移除了特殊 0 槽及其 `Super+'` 快捷键；数字 0–9 均为普通栈槽。

## 功能边界

- 保留左主列、手风琴栈、焦点列、monocle、隐藏客户端 chrome 和列镜像。
- 保留现有窗口插入、关闭、移动、交换和焦点行为。
- 保留现有快捷键和外部命令。
- 继续以单输出、单 seat、无传统浮动窗口为正式支持范围。
- 不增加 workspace、IPC、动态配置重载、动画或窗口规则系统。

## 架构

将现有实现逐步分成四层：

1. 纯状态模型维护 master、stack、expanded、focus_side、monocle 和列方向，并定义始终成立的不变量。
2. 纯布局计算接收状态、输出尺寸和配置，产生窗口与 chip 的可见性和几何结果。
3. River 适配层接收协议事件，把纯模型的结果提交给 compositor。
4. 平台辅助层负责配置、进程启动、输入设备和 titlebar buffer。

迁移采用小步替换，不一次性重写。每一步都必须保持可构建，并用现有行为测试作为约束。

## 可靠性

- titlebar 的 shm buffer 在 compositor 发出 `wl_buffer.release` 后才回收；绘制使用安全的多缓冲策略。
- 所有 River、Wayland 和 libinput 协议对象都有明确所有权和销毁路径。
- 比例、尺寸和整数运算在进入布局前校验，非法配置回退到默认值并记录原因。
- 窗口数超过屏幕可容纳范围时使用确定、不会产生负尺寸或越界的降级布局；不把它定义成新功能。
- 可恢复错误记录日志并继续运行；破坏核心协议状态的错误明确退出，避免带着损坏状态运行。
- 构建和测试成功后才更新日用二进制，并保留上一份已知可用版本。

## 测试

纯状态测试覆盖新增、关闭、移动、交换、焦点切换、monocle 和镜像。纯布局测试覆盖零窗口、单窗口、多个窗口、极小输出、非法配置和 chip 无法全部容纳的情况。

协议层保持薄，不模拟整个 compositor；使用 Debug/ReleaseSafe 构建、单元测试和实际 River 会话冒烟测试组合验证。

## 兼容与升级

固定 River、Zig、zig-wayland 和 zig-xkbcommon 的已验证版本。依赖升级独立进行，不与功能或重构混合；升级后先构建和测试，再进入日用环境。

River 0.4 及其 `river-window-management-v1` 是目标平台。tri 只绑定自身需要的最低协议版本；新协议版本出现时不自动采用。

## 完成标准

- 原有肌肉记忆和可见行为保持不变。
- 核心状态和布局可在不启动 River 时测试。
- 配置错误和极端窗口数量不会产生非法几何或无提示失败。
- titlebar buffer 生命周期符合 Wayland 协议。
- 日志能定位初始化、协议、配置和绘制错误。
- 任一阶段都可以回到上一份已知可用二进制。
